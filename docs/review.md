# Review agent

`alsp review --repo <path> --base <rev> [--head <rev>] [--agent codex|claude|agy]` builds an evidence pack, reports mechanical findings, optionally asks one or more read-only coding agents to inspect the changed routines, proves the agent citations against changed lines and pack symbols/edges, merges nearby agent duplicates within a symbol, and appends findings to `<repo>/.alsp/findings.jsonl`. `--print` prints the shared prompt with the pack and diff for another agent. Agent command paths can be overridden with `ALSP_AGENT_CODEX`, `ALSP_AGENT_CLAUDE`, and `ALSP_AGENT_AGY`.

The pack and diff are untrusted data. The prompt delimits them as data, agent processes use read-only modes, and the proof step drops findings that cite no known file and line. Only lines beginning with `FINDING|` are parsed; `NO FINDINGS` means an empty result. Malformed finding lines are counted in the report footer. An agent run with neither valid findings nor `NO FINDINGS` gets one unparsed row. Each agent's complete output is saved to `<repo>/.alsp/raw/<head-short>-<agent>.txt`. A change too large for one prompt is split by crate, then by file when one crate is still too large; the report says how many scopes it used, and a single file larger than a prompt is cut and noted. Agents run concurrently; each timeout defaults to 600 seconds and can be set with `--timeout`. The report names the agent that timed out. An agent runs in its own process group and the whole group is killed on timeout or when the agent exits, so a background child cannot hold the run open. Each of an agent's stdout and stderr is capped at 4 MB (the raw file too); a cut is noted in the report. An empty diff starts no agent. The agent prompt closes its data blocks with a per-run random id, so diff text cannot forge the closing tag. Agent findings at the same spot merge across sources: same file, lines within 3, and either the same changed symbol or both outside any symbol; the highest severity and longest text win. Finding lines may contain `|` in the text and may cite repo-root files such as `Cargo.toml`.

The new findings ledger is append-only: `alsp ledger mark <id> held|not-held` adds verdict rows; it never rewrites earlier findings. `alsp ledger list [--repo <path>] [--source <s>] [--unmarked]` displays findings for review. `alsp ledger stats` reports totals and held rates by source. Existing `.alsp/ledger.jsonl` files are read alongside `.alsp/findings.jsonl` and are never rewritten. `alsp ledger import-gaps docs/gaps-first-read.md` imports the ten gap verdicts in that file as an example of the ledger's input.

## What the report lists

After the agent findings (so those stay first) the text report has a `Changed symbols` block: one row per function, type or constant the range touched, ordered by file and line, as `<added|modified|removed> <name> <file>:<first>-<last>` (up to 12 rows, then `+N more (alsp pack --base <rev>)`; modules are left out). The `name` is what `alsp cover` and `alsp gaps` take, and so is `<file>:<first>`; an ambiguous name is reported by those commands with the longer names to use. This is the same list in every tier, `--quick` included, so an agent does not need `git diff` to choose what to cover. With `--format json` the same rows are `changed_symbols` (`name`, `file`, `line`, `end_line`, `change`), up to 25, with `changed_symbols_more` counting the rest. Only symbols the index resolves are listed; a Rust range that changed no routine says `Changed symbols: none`.

## Ad-hoc use

`alsp review` with no arguments reviews everything since the last review, including uncommitted work, and says up front what it will cost. Run it after a batch of changes; there is no hook involved.

- **Base.** `--base` when given. Otherwise the end of this branch's last review, recorded in `<repo>/.alsp/reviews.jsonl` (one row per finished review: branch, the checked-out commit, the commit actually reviewed, whether uncommitted work was included). The record is used only while its commit is still an ancestor of `HEAD`; after a rebase or reset it falls back to the merge-base with the default branch (`origin/HEAD`, else `main`, else `master`) and the first line says so. With neither a record nor a default branch the command exits 2 and asks for `--base`. A `.alsp` that git tracks is repository-provided, so its records are ignored (a committed record could hide changes). The file is append-only and is never written through a symlink.
- **Head.** `HEAD` plus uncommitted work: tracked edits and deletions, and files you have staged as new (`git add`). Untracked files are not included unless you pass `--untracked`. `--committed` reviews commits only. `--head <rev>` reviews that commit only. A run with `--head` other than `HEAD` is not recorded.
- **Untracked files are opt-in.** When untracked, non-ignored files exist and are not included, the stderr first line ends with `N untracked file(s) not reviewed (pass --untracked): a, b, ...` (up to five names). `--untracked` adds them, except files whose name looks like a secret (`.env`, `.env.*`, `*.pem`, `*.key`, `*.p12`, `id_rsa*`, `id_ed25519*`, `credentials*`, `*secret*`, any letter case) and files over 1 MB; each is listed on stderr as `skipped untracked <path> (<reason>)`. The name filter applies to untracked files only: a secret-named file that git already tracks is reviewed like any other tracked file when you edit it, so keep secrets out of git.
- **How agents see uncommitted work.** `alsp` builds a snapshot commit of the work tree in a throwaway copy of the index (`git add --update` on a copy of your index, so staged additions are kept and untracked files are not; with `--untracked`, the allowed untracked files are added too; then `write-tree`, `commit-tree -p HEAD`, fixed identity and date) and uses it as the review's head. The diff, the evidence pack's export and index, and each agent's `git archive` export all use that commit, so the export holds your uncommitted work (and untracked files only with `--untracked`) and agents still run in a private export, never in the checkout. Your index, work tree and refs are not touched; the only trace in `.git` is unreferenced objects that `git gc` collects. An unchanged work tree gives the same snapshot id, so a second run right away has an empty range. The next run starts from the snapshot, so it shows only newer edits. If the snapshot cannot be built (for example an unreadable file passed in by `--untracked`) the run exits 2 and names `--committed`.
- **Tiers.** `--quick`: mechanical evidence only, no agents, no coverage or gaps; seconds on a warm index (a Rust change that has never been indexed costs one index build, about 30 s on a large workspace), free. Default: also the agents named in `.alsp/enabled` (a hand-written settings file, e.g. `agent = claude,codex`; `with` and `timeout` keys are accepted and ignored); none when none are configured. `--full`: also `--with coverage,gaps` (runs tests, Gemini cost through sdd). Explicit `--agent` and `--with` replace what the tier would choose.
- **What is sent to agents.** Each agent receives the diff and the evidence pack in its prompt, and reads files from its private export of the reviewed commit, so it can read the whole committed tree plus whatever the snapshot added. Everything in that export and diff goes to the external model service behind the agent (claude, codex, agy). By default that is committed history, tracked edits and staged additions: no untracked file. Gemini (`--with gaps`) receives function bodies of changed routines only. Check `git status` for untracked secrets before `--untracked`; the filter above is a safety net by file name, not a scanner of contents.
- **First line.** On stderr, so stdout stays the report: `alsp review: base 0123abcd (last review of feat, at 0123abcd); head 0123abcd + uncommitted changes; default tier, agents claude,codex: ~2-10 min, uses agent quota`. An ad-hoc range with nothing in it prints `nothing to review` on stdout and exits 0 (with `--format json`, `{"nothing_to_review":true,...}`); an explicit `--base` keeps the full, empty report.

Measured on a mid-sized Rust workspace (2026-11-14, release build): `--quick --base HEAD~3` took 29 s cold (index build) and 0.16 s warm; a no-argument `--quick` run took 0.09 s.

## Trust rule

Indexing a commit runs its build scripts and proc macros and reads its cargo configuration, whatever the tier (`--quick` included); `--full` and `--with coverage|gaps` also run its tests. `alsp review` has no `--no-build`, so only point it at repositories and commits you trust. To query an untrusted repository use `alsp sym|refs|tests --no-build` (without `--run`) against a cached index (docs/query.md, "Trust and cost"). Whatever the repository, `alsp review` never runs a program named in the repository's `.git/config` (fsmonitor, external diff, textconv, clean/smudge filters, hooks, a gpg program, a remote's program) when it takes the work-tree snapshot, diffs or exports the commit, and it neither enters submodules nor fetches missing objects of a partial clone; docs/query.md, "Trust and cost", lists what that does not cover.

## Confinement

Each agent runs in its own private export of the head commit, not in the reviewed checkout. `alsp review --agent ...` creates a fresh temp directory (mode 0700) per agent, fills it with `git archive <head> | tar -x` (no shell), runs the agent there, and removes it afterwards on success, failure, timeout and panic. The diff and pack still travel in the prompt, findings still cite repo-relative paths, and the raw output still goes to `<repo>/.alsp/raw`. The `Agent time` line includes the export time (`export Nms`). If git or tar is missing or the temp directory cannot be made, that agent is skipped with the reason and the mechanical findings are still reported.

What this stops: an agent that writes or deletes files in its working directory changes only the throwaway export, so the reviewed checkout stays clean (`git status --porcelain` empty), and uncommitted or untracked files in the checkout are not visible to agents at all. The export has no `.git`, so history commands (`git log`) find nothing, and the repository's untracked agent config (for example an ignored `.claude/`) is absent. What it does not stop: the export is an ordinary directory, so an agent can still write anywhere the user account can write, outside the export, by any command it is allowed to run. There is no OS-level sandbox. Symlinks committed in the repository are exported as symlinks and can point outside the export. Submodules are not exported (noted in the report), and `export-ignore` rules in `.gitattributes` drop files from the export (also noted). Project instruction files (`CLAUDE.md`, `AGENTS.md`) are exported and still read by every agent, so they can carry prompt injection.

Per-agent switches: claude runs with `--setting-sources user --strict-mcp-config` (project and local settings, hooks, and project MCP servers are not loaded) and `--permission-mode plan`; codex with `--sandbox read-only --ignore-rules`. agy is the weakest. Verified on 2026-11-14 with agy 1.5.9: `--mode plan` has no effect while `--disable-slash-commands` is set, and headless agy wrote files with its file tool and with `sh -c "echo hi > f"`, inside and outside the workspace; `--sandbox` made it worse. An allow-list of read-only commands was tried and rejected, because allowed tools write through their own flags (`sed -n '1w f'`, `git log --output=`, `rg --pre <cmd>` runs a program). So agy gets a default-deny per-session `--settings` policy with no allow rules: `{"permissions":{"deny":["command(*)","write_file(*)","write_file(/)"]}}`. Every shell command and the file-write tool are denied (deny beats allow); agy still reads and searches with its built-in file tools, and the review prompt tells agents to carry on with what they can read when a tool is denied. Remaining risk: agy's other built-in tools are not covered, for example any MCP tools configured in your agy settings, and reading is not confined, so agy can read files outside the export by absolute path. The export step has the same timeout as the agent (`--timeout`). Treat agy as confined on a best-effort basis, and review only trusted repositories and commits. `alsp` also refuses to write through a symlinked `.alsp`, `.alsp/raw`, or ledger or raw file.

## How often findings held

One measurement, 2026-11-14, on seven commits of a private Rust application (each reviewed with `alsp review --with coverage,gaps`; Claude, Codex and agy took part, not every one on every commit). Three of the commits changed only test files, so they produced no findings: test files get no coverage or gap data, and the agents reported nothing.

Verdict method: each finding was judged held or not-held by an agent other than its author, reading the code at that commit. Codex judged Claude, agy, coverage, gap and heuristic findings. agy judged Codex findings. No mutants were run, so gap verdicts are a reading of the tests. Verdicts live in `<repo>/.alsp/findings.jsonl`; overrule any with `alsp ledger mark <id> held|not-held`.

| Source | Held | Judged | Held rate |
|---|---:|---:|---:|
| Claude | 18 | 20 | 90% |
| agy | 6 | 6 | 100% (small sample) |
| Codex | 4 | 11 | 36% |
| Predicted test gaps (Gemini, P(catch) < 0.50) | 111 | 167 | 66% |
| Uncovered changed lines | 23 | 50 | 46% |
| Heuristic (signature change, callers outside diff) | 0 | 1 | none |

Caveats:

- The judges differ. agy judged every Codex finding and Codex judged everything else, so the Codex rate may partly reflect a stricter judge.
- Samples are small, and each finding had one judge, not a panel.
- Uncovered-line findings were often error paths for allocation failures, which judges called not worth testing.
- agy timed out on the largest commit at the old 120 s default. The default is now 600 s.

Cost (Gemini, called through sdd's `decide` command so sdd's budget sees it): about $0.09 per review of a ~600-line diff (100-mutant budget). Agent time was 2 to 10 minutes per review, with agents running in parallel.
